# 数据分级与禁入规则

便利不能先于边界。P0 默认只证明：用户可以在自己的设备和私有仓库里建立个人专业 Brain。它不自动获得处理公司或客户资料的权利。

## 五级数据

| 级别 | 例子 | P0 默认 | 外部模型调用 |
|---|---|---|---|
| `public` | 公开文章、公开演讲、用户主动保存的公开资料 | 允许 | 可用，但保留来源 |
| `personal_private` | 用户自己的笔记、偏好、个人判断、私人日程摘要 | 本地允许 | 默认关闭；用户明确选择后才可用 |
| `work_authorized` | 用户有权处理、且组织政策允许进入个人工具的工作资料 | 条件允许，单独 source | 仅按组织政策与用户明确授权 |
| `org_restricted` | 内部保密资料、未公开经营信息、受限员工数据 | 个人版禁入 | 禁止 |
| `client_or_secret` | 客户机密、凭据、密钥、支付信息、受监管原始数据 | 禁入 | 禁止 |

## 默认动作

- 默认存储：本地 PGLite + 私有 Git。
- 默认导入：从一个高价值、低风险资料集开始，不做全量抓取。
- 默认 source：个人与条件允许的工作资料必须分 source，不能混成一个权限面。
- 默认模型：没有明确选择时，不把 `personal_private` 发送给外部模型。
- 默认凭据：密钥只进凭据管理器或运行时环境，不进 Brain 页面、Git 或评测语料。

## 组织与客户边界

个人设备、个人 Brain 和个人 AI 席位不会因为“工作方便”自动变成公司端点。若组织希望接入内部或客户资料，应另立 Company/Enterprise 项目，明确 owner、设备、权限、日志、留存、删除、模型供应商和法律评估。

## 删除与可迁移

用户应能：

1. 找到原始 Markdown；
2. 删除单页及派生索引；
3. 导出自己的资料；
4. 看见资料来自哪个 source；
5. 知道哪些内容曾被外部模型处理。

P0 的测试只验证 source 隔离，不等于完整的企业权限认证。
